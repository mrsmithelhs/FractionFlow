# App shell and navigation contract

Plan 64's first slice applies to the existing surrounding shell; it is not certification of every episode. Plan 43 owns deliberate progression, Plan 52 feedback meaning, and [the episode presentation contract](episode-presentation-contract.md) task-internal arrangements. The app owns navigation, focus, episode lifetime and the progression descriptor; task renderers place the supplied progression with accepted work. The comparison record controller owns eligible observation capture and storage.

The view switch precedes episode navigation in DOM/keyboard order, followed by task work and support controls. “Read the steps” / “Show the picture” switch views; “Back to start” reaches the start page; “Try this problem again” starts the same problem fresh. Next and any reflection Continue remain with accepted task work. The final session result has one “Back to start” action and “Practice complete.”; the separate shell return is hidden. Controls wrap rather than requiring a fixed viewport. Task Help remains task-owned.

Standalone return is immediate, including unsubmitted work. In a composed session, returning from an unfinished episode opens “Leave this practice? Your place will not be saved.” with Stay and Leave; even a fresh episode uses this existing rule. Stay and Escape retain work and position and restore focus; Leave ends the session. Returning from an accepted intermediate or final episode is immediate. Restart is immediate and resets the current episode while preserving the session index. These are explicit existing exceptions, not a universal dirty-work rule. Any new confirmation or reset policy requires owner approval.

“Place” refers to ephemeral session position and current work. Return, restart and exit do not clear saved comparison observations or turn off remembering. Captured pending writes follow the existing ordered storage process and may fail; no navigation action promises they have already saved. Record eligibility remains separately defined by Plan 63.

A refused preparation leaves valid current work and position available and presents a neutral retry/return notice. A session display failure after a transition has committed instead safely exits to the entry page with a notice; it does not promise rollback. Successful installs focus the episode landmark (subject to existing task-specific focus), and return focuses the entry heading. Retired callbacks must not operate on a later episode or remounted shell. Future episode migrations and broader policy changes require separate review.
