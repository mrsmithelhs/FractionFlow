## Requirement 0 — scope and stop

Run preflight. Propose a small inventory of actual representation responsibilities,
two candidates at most, decision criteria, falsifiers and research limits. Stop
for orchestration approval before dossier work. Existing evidence first; if a
specific instructional question changes the choice, request a targeted primary
source search (normally at most three studies/guides), with relevance and stop rule.
No broad survey, browser/prototype/build/full-suite/route run or learner study.

## Requirement 1 — honest gap assessment and one recommendation

Map Roadmap33–37 obligations to precise evidence: current task responsibility,
exact operation meaning, supplied versus established form, state continuity and
remaining uncertainty. Distinguish visual/linear access from bar/line switching;
symbolic distance from directed movement; renderer animation from learner reasoning.
Owner task acceptance and automated evidence do not demonstrate learner transfer.

For each candidate specify one responsibility, problem bounds, response and what
the learner must infer. Reject passive replay/Continue and an aligned solution
model masquerading as an independent task. Explain why the selected gap matters
more now than adding another task variant. Give two concrete journeys, wrong/revised
and requested-help behavior, concise copy and unmeasured narrow/Chromebook sketches.
For movement, define start, direction, distance, end, operation order and unit;
avoid asking for a result already displayed. For switching, name one exact switch
moment and preserved state, not a universal representation framework.

## Requirement 2 — mathematical, access and continuity contract

Check roughly 4–6 illustrative examples with existing exact APIs, not authored
answer keys. Keep the proposed domain proper fractions/nonnegative quantities;
if a selected operation crosses an unsupported boundary, stop rather than silently
expanding scope. Specify honest scale, benchmark/partition semantics and which
quantities are given, tentative or accepted. No automatic larger denominators or
viewport-derived correctness. Preserve raw forms and learner-established work.

Describe pointer/touch, keyboard/non-drag/linear participation, explicit submission,
focus/feedback associations, reduced motion, help and shared direct progression.
State which drafts, assistance, accepted forms and identities survive a change;
reject stale callbacks and handle capability refusal truthfully. Accessible cue
differences are explicit, not claimed identical reasoning. No wordy directions,
new global control conventions or empty acknowledgment steps.

## Requirement 3 — source slice, evidence and readiness disposition

Recommend one compact later implementation: authoring inputs/identities, ownership,
intents/scene withholding and replay boundaries. Name actual missing seams and
current reusable components without assigning a schema number or refactoring a
general engine. Refresh geometry/evidence tooling against current capabilities;
no historical problem alone justifies a new tooling packet.

Map exact all-record checks versus mounted representative evidence. Specify ordinary
assertions/mutations for unit drift, wrong start/direction/distance or mapping,
premature answer reveal and lost draft/assistance across the selected switch.
Preserve historical fixtures and isolated receipts. Recommend owner choices and
Phase4 prerequisite/exit disposition without declaring closure; retain deferred
movement/switch cases explicitly. No mixed strategy or OQ-24 decision belongs here.
