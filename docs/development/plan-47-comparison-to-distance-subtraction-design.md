## Goal and reason

Recommend ONE concise task connecting which fraction is greater to how far apart
the amounts are. Existing subtraction uses takeaway; a distance/comparison meaning
must add a distinct conceptual connection rather than duplicate that episode with
new wording. Explicitly choose between reading a represented distance and computing
it symbolically before model verification. Do not quietly supply the whole answer
through prefilled gap labels when the stated purpose is learner computation.

## Requirement 1 — recommend one short learner journey

Begin from neutral wording such as **How far apart are these amounts?** If first
judging order is part of the adopted task, it must be actual learner work rather
than a prompt presupposing which amount is greater. Preserve original first/second
labels when deriving subtraction order. Do not silently change the problem or
introduce signed negative differences.

Specify what appears before comparison, before difference, on requested help,
after errors and after acceptance. Apply Plan44's one-chosen-model rule while a
comparison response is pending; any paired model later must have an explicit
instructional purpose. A learner-established comparison may legitimately become
provided context for a new distance question; it is not another copy of the same
response. Recommend whether the first slice begins with common-unit pairs or
adds renaming, with a concrete reason and a small source boundary.

Define one recommended representation: honest aligned bar comparison, measured
line interval, or another existing-supported option. Do not implement both to
avoid making the design choice. Distinguish interval LENGTH from endpoint location,
unit count from part size, and unit whole from graphic domain width. Models may
support learning; do not describe visual answer-reading as independent computation.

Include wrong/revised response, useful requested help, both access paths, non-drag
touch/keyboard, More/Less and focus/provenance policy. Keep original fraction forms,
stacked notation, one active question and concise local feedback. No full conversion
episode plus final reflection by default. Use shared direct progression after the
last meaningful responsibility; no empty Finish or explanation-response burden.

Equality/zero distance must be dispositioned explicitly. If comparison already
settles the meaningful work in that case, avoid an empty compulsory extra question.
Any shorter branch derives from authored math/recipe, not performance-based schedule
mutation. Wrong answers do not select a different task or silently lower support.

## Requirement 2 — exact content and source contract

Use existing compare/subtract/equality/conversion APIs to derive unsigned distance
as larger minus smaller without adding a signed/absolute-value arithmetic operation
by assumption. Preserve source order separately from computational order and
unreduced display forms separately from normalized identity. Verify roughly 6–8
illustrative ordered pairs with swaps, equality, unlike units and at least one
case exposing a unit/order mistake; no hand-authored correctness table.

Bound proper-fraction/domain and actual representation capacity. A common-unit
bar needs a valid readable common partition; symbolic or benchmark reasoning does
not automatically require a rendered LCD. No larger-denominator policy, improper/
mixed work, random content, mastery rules or persistent tracking.

Recommend compact task records, fixed schedule/branch derivation, learner intents,
classification/scene withholding, response/helper ownership and old replay preservation.
No renderer math, general strategy engine or parallel navigation mechanism. Identify
how this composes with comparison without creating per-item special-case modules.
