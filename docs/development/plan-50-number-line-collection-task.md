## Requirement 1 — compact exact content and pure checkpoint

Implement a reusable collection record, not per-problem modules or answer tables.
Pin set/item/member identities and revisions, original forms, authored member order,
purpose and common lattice. Four adopted records, in the following member order:

| Record purpose | Three original forms | Lattice |
|---|---|---:|
| Equivalent pair plus contrast | 3/4, 1/2, 3/6 | 8 |
| Distinct ordering | 7/8, 1/4, 1/2 | 8 |
| Thirds/equivalence | 4/6, 1/3, 2/3 | 6 |
| Endpoints | 4/4, 0/2, 2/4 | 4 |

Admission: exactly three unique member IDs; exact original nonnegative forms in
[0,1], denominators <=8; lattice in {4,6,8}; every value matches an exact offered
i/lattice point; at least two distinct values and one unused offered point.
Raw denominator need not divide the lattice if the value matches. Reject content
capability failures explicitly, never call them wrong learner mathematics. Preserve
equivalent raw forms and distinct member IDs. Derive positions/order/equality with
existing exact APIs, independently of renderer coordinates. No sorted input order
or answer-only offered set. All-equal authored cases stay deferred but arbitrary
draft collisions are legal. No automatic source-bank/random expansion.

Use one fixed place-collection -> resolve schedule. Instructional state owns
selected member, durable member-to-candidate-or-unplaced map, help/support and
evaluation revision. Pointer hover may be local; committed draft placements must
survive view/remount. Distinguish draft locations from accepted mathematical work.
Validate active collection/member/candidate/phase identity atomically. One Check
evaluates a complete map: incomplete Check identifies unplaced members without
grading the placed subset; wrong Check marks member feedback without target answers,
retains everything and permits editing every member. Editing clears that member's
stale feedback and marks the collection as needing another Check. Acceptance
establishes the whole map atomically. No auto-accept per label or misconception
diagnosis from an incorrect placement.

Persist exact contracts, admission tests, independent all-record math evidence,
and literal replay/version compatibility in checkpoint-1.md under the report
folder. Stop for review before broad app/render/serializer integration. Reuse one
authoritative common episode boundary; do not create competing public histories.
Historical definitions/replays remain immutable; no schema number preassigned.

## Requirement 2 — mounted placement and honest co-location

Implement the approved geometry/control contract. Keep a visually distinct unplaced
tray, persistent authored-order member selection/status list and one selected
member's direct movement controls. Dragging, line taps and non-drag keyboard/touch
controls produce the same exact candidate identities. First movement explicitly
chooses an endpoint; don't silently imply midpoint or correct placement. Maintain
clear pick-up/focus/selection affordances and nearest-drop preview. Cancel, lost
capture or invalid drop restores the prior placement, including unplaced.

Equivalent or colliding draft tokens share ONE exact anchor. Use separate vertical
label rows with tethers, preserving authored order and each selectable identity.
Handle all three draft tokens at one anchor; never shift coordinates to avoid
collisions. Reserve height and keep labels in bounds. Close neighboring anchors
must not produce overlapping interactive targets; the persistent member list
remains an unambiguous selection route. Specify any bounded packing adjustment at
the mechanism gate, not by silently hiding tokens or changing values.

Use shared stacked fractions, calm styling, 44x44 CSS-pixel targets and concise
instructions/status. Duplicate visual label controls need no extra Tab stops when
the persistent list provides equivalent keyboard selection. Announce placement
and co-location neutrally without treating draft equality as correctness. No
duplicate prompts/transcript, compulsory acknowledgment or empty Finish.

Linear access is the same task and exact lattice: stable members with unplaced/
position status, selection and direct placement controls, one Check and associated
feedback. It is not a new bar/line representation switch. Keep existing More/Less
only, identical eligible locations/answer rules, explicit projected support policy
and optional non-answer-bearing help; no performance adaptation. Freeze support
per episode and record requested assistance without claiming independent mastery.

Preserve selection, placements, drafts, assistance and appropriate focus across
view/help/resize/remount. Revoke retired item/render/member callbacks; keyboard
controls must work after repeated rerenders. Restart, Next and return/re-entry
create fresh state. Failed navigation leaves accepted work inspectable. Use Plan43
direct local Next/final Back, never a parallel progression implementation.
