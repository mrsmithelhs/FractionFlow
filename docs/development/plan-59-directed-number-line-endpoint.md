## Requirement 2 — concise mounted endpoint task

Show one mathematical expression with stacked fractions and a supplied start marker
on [0,1], plus one brief placement instruction. Avoid repeating the expression in
heading, subheading and prose. Distinguish fixed start from an initially unplaced
learner endpoint tile; use a separate starting tray and stable line layout. Reuse
nearest-target highlighting, cancellation, tile containment and large step correction
where suitable. Direct non-drag pointer/touch and keyboard spatial controls remain;
linear exact-position choices disclose their different cue structure. No auto-check.

Use shared retry/neutral incomplete/success styling, feedback associations, visible
focus and one deliberate announcement path. Requested local help may explain
start/direction/equal steps without locating the end. Its toggle, draft and assistance
survive ordinary view/resize, but restart/Next resets appropriately. Do not include
a generic help paragraph that merely repeats all visible directions.

One whole is the complete [0,1] line width U. Start a/d is x0+(a/d)U; amount b/d
is b equal intervals FROM THE START. Addition goes right; subtraction goes left.
Accepted arrow spans supplied start to accepted endpoint with correct arrowhead,
length and order; never draw the completed interval before acceptance. Static
verification is sufficient; optional motion may not introduce a new mandatory effect
or timer. Reduced motion retains the immediate inspectable result.

After acceptance retain start/expression/result/interval with concise acknowledgment,
and shared Next/final Back. No extra direction question, result-entry quiz, reflection
or empty Finish. App supplies verification rather than attributing it as separate
learner work. Distinguish unsigned magnitude from operator direction, without
introducing signed fraction arithmetic.
