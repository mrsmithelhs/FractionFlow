## Requirement 1 — compact data and pure instructional contract

Start with the revised 12 ordered Plan44 pairs: positive proper fractions,
source denominators <=10, four outcomes per relation. Treat the report evidence
as illustrative input to materialize/validate, not a production answer table.
Derive relation, normalized identity, proper-fraction/capacity bounds and hint
context from existing pure math APIs. Preserve unreduced source forms and operand
order in display and replay; equality is a genuine response. Do not use LCD<=30
as a universal restriction when only the individual source bars are rendered.

responses and malformed records fail explicitly; no implicit coercion to a valid
relation/model side. Private expected relation belongs upstream for classification.

## Requirement 2 — one concise response and assistance contract

Show both original stacked fractions once. Prompt **Compare these fractions.**
Use one native keyboard-operable relation group: < / = / > with concise meanings
and full accessible names tied to stable operand order; minimum 44x44px targets.
Selection is a draft until Check. No second verbal/symbol judgment, encounter
acknowledgment, repeated heading/prompt or compulsory conversion response.

Keep one optional help disclosure initially, rather than several competing help
buttons/paragraphs. It contains notation guidance, one item-appropriate reasoning
cue and choice of which source fraction to model. Cues must suggest useful thought
without setting the correct relation; derive any numerical target through exact
APIs. Preserve a distinction between reasoning assistance and notation assistance.
Do not equate a wrong inequality selection with a diagnosed magnitude misconception.

First model request commits either source side for this problem attempt. Once
chosen, show only that source model before acceptance, with honest whole/partition
geometry and a truthful benchmark if useful. No switching to the other source,
second filled model, or blank comparator that reads as zero. Avoid spent/inert
controls: replace the choice UI with the chosen labeled model/access equivalent,
or another concise truthful treatment approved at the gate. Help close/reopen,
wrong Check, view switching, resizing, zoom and remounts preserve the choice and
relation draft. A stale second request cannot overwrite the first accepted choice.

The rule is per fresh problem attempt: Next, explicit restart and return/re-entry
use existing fresh-state rules, allowing a new choice. Do not introduce persistent
cross-attempt restrictions or learner history. Assistance provenance records actual
help/model requests; successful assisted work is not independent mastery evidence.

Wrong Check gives brief local recovery, retains all relation choices and the
chosen model, and permits revision. Restore deliberate focus to a current connected
control; link feedback accessibly. No elimination of alternatives, answer-bearing
model reveal, lock reset or forced new task after an error. Generic wrong-Check
feedback may be projected; expected relation and correct-option flags may not.

Visual and linear paths obey the same choice/withholding rule and offer equivalent
selected-source information. The hidden view must not expose the other source
model or answer-bearing accessibility text. Preserve requested aid/draft through
view changes; neither renderer decides mathematical truth or support policy.
