## Goal and observed problem

The start destination currently uses “Back to start” in standalone practice but
“Back to practice” in composed sessions and at their completion. The same session
branch confirms leaving an unfinished episode, while standalone return is immediate.
Plan63 now separately remembers selected observations: losing a session position
must not be confused with deleting that record. Plan62 covered inside-episode
presentation, leaving this shell-level inconsistency outside its first slice.

Define recognizable surrounding controls and apply a small shared slice. Use
“Back to start” for the same start-page destination; preserve meaningful differences
between view switch, restart, Next, return and session exit. Do not manufacture
uniformity through redundant dialogs, instructions or extra completion steps.

## Requirement 0 — investigate, propose and stop

Run preflight. Inventory shell control labels, styling, order, visibility, destination,
focus and reset semantics across standalone comparison, one arithmetic/construction
task, one placement task and the composed session. Include initial, draft/help,
accepted/next, final, navigation failure and session exit states in both access paths.
Inspect callback lifetime and current practice-record preservation; no all-item audit.

Produce a navigation/loss matrix: fresh task with no work, unsubmitted input or
placement, accepted current result, partially completed composed session, final
completion, and failed navigation. For each distinguish discarded current draft,
session position, retained saved observations and preferences. Do not infer dirty
state from rendered text or collapse everything into “progress”.

Propose one concise label/control arrangement and exact source paths. Preserve
existing policy unless a new behavior is explicitly approved. Recommend whether
confirmations earn their interruption for each loss case; do not automatically
spread session dialogs to standalone tasks. New confirmation/dismissal/reset rules
are owner decisions: relay them through orchestration before source. If a broader
policy is deferred, implement the unambiguous label/layout corrections and document
the explicitly approved existing exception instead of silently changing behavior.

Stop for approval of shell-proposal.md, maintained-contract proposal, matrix,
literal copy and test scope. No source at this gate. No advisor for the paper gate.

## Requirement 1 — bounded shell implementation

After approval centralize/reuse the start-destination wording, including session
completion, and make common navigation/control placement and treatments predictable.
Do not change where an action goes merely to match its label. Preserve Plan43's
deliberate progression and no empty Finish step, and Plan62 task responsibilities.

Scope includes common surrounding controls: visual/linear switch, return, restart,
progression placement/visibility, session Stay/Leave and neutral navigation refusal.
Keep task Help inside its accepted task contract. Preserve which controls are
available during work, accepted results and completion; avoid duplicate exit paths.
No extra headings, menus or developer explanations in the learner shell.

Keep saved comparison observations separate from ephemeral work. Returning/leaving
does not clear the record or disable remembering. If a warning is retained, say
exactly what is lost and avoid implying all activity disappears. No new resume,
beforeunload interception, persistence, support policy or inferred learner state.

Preserve connected visible focus, DOM/keyboard order, dialog Escape/Stay/Leave,
entry/episode landmarks and stale callback rejection. A refusal retains valid work
and remains neutral; an unrecoverable display failure must follow accepted safe
fallback rather than promise rollback. Do not widen this into a transactional
renderer refactor or global focus rewrite.

## Requirement 2 — contract and evidence

Maintain a compact shell contract naming owners, labels/destinations, control
arrangements, approved loss/confirmation policy and justified exceptions. Separate
implemented rules from future migrations. Reference rather than duplicate Plan52
feedback and Plan62 internal layouts. No claim to have certified every episode.

Use matched representative standalone/session views at 360×740 and Chromebook
1093×614, keyboard/linear, pointer and meaningful enlarged text/reduced motion.
Verify actual control order, visible labels, focus and loss/preservation behavior,
including final return and early exit. The known entry-title reflow issue is not
automatically in this scope; record it separately from changed shell geometry.

Test Stay preserves draft/help/position and Leave does exactly the approved matrix;
completed return adds no redundant confirmation. Verify no record deletion/disabled
preference on return, stale controls after exit/restart/destroy, and failure retains
or safely exits work according to the existing boundary. Use actual mounted controls,
not hidden/forced clicks. Add focused assertions for destination/copy/order/policy,
with one meaningful failing-first check. Class presence alone is not visual proof.

Focused checks during edits; final suite/build/lint/diff and one genuinely isolated
historical route matrix if shared routing/renderer branches changed. Resolve absolute
working directory/source/output snapshot before launch; never fall back to shared
historical output after setup failure. Preserve old receipts and exact timing.
One consolidated cold read-only Terra-medium review if behavioral changes are
substantial; none automatically for mechanical labels/CSS. No duplicate parent
review, Sol/Astra, silent substitution or child fan-out. Record actual limits.
