## Goal and why this packet exists

Implement DECISION-042's first reusable task-pattern increment. Separate the
mathematical problem from the learner responsibility so compatible problems can
reuse shared behavior instead of acquiring bespoke episode branches. Provide
shorter full additions whose equivalence work is used in the operation, rather
than appending another check to an already long episode.

This is a small demonstrated abstraction, not a universal episode engine.
Two named patterns across multiple existing problems must earn their place
through present reuse and reviewable learner behavior. Additional compatible
numeric records should need compact data and deterministic validation, not
per-problem app/render code or hand-calculated answer tables.

## Requirement 1 — Two compact full-operation patterns

For two-renaming examples, use:
`encounter → transform-left → transform-right → operate → resolve`.
Retain encounter acknowledgment. Display the supplied target as brief context
such as “Use twelfths,” with no separate acknowledgment. Omit unit notice,
denominator selection and reflection for these new definitions. One numeric
operation submission is followed by result/finish navigation, not another sum
or equivalence quiz. Existing resolve already avoids a second numeric sum;
do not claim a new saving there. Entry counts are not gesture/time measures.

- **Construct:** ask for the numerator that preserves the source amount at the
  supplied denominator. Withhold the expected numerator and completed target
  amount before acceptance; a neutral target template must mean unknown, not zero.
- **Inspect/keep/repair:** present an authored candidate without revealing its
  validity. Learner keeps it or changes its numerator. Validate exactly. A valid
  same-numerator change is mathematically accepted as unchanged/valid while the
  actual submitted action remains recorded; do not call it a math error because
  the learner chose a different action. False keep and invalid repair recover
  at the same entry. Repair may take a choice and numeric input; do not claim
  every fixed task is one gesture.

Only accepted forms feed the addition. Pattern assignment never changes in
response to errors/help/view changes. Apply the pattern to every required
renaming side; an operand already in target units is provided, with no invented
learner transformation. Reject zero-renaming items for these patterns rather
than adding filler work. Keep future one-side capability out of learner reach
unless its complete path is separately covered and approved at Requirement 0.

## Requirement 2 — Compact data and demonstrated reuse

Use existing instances at target 12:

| Existing instance | Proposed first assignment | Inspection stimulus example |
|---|---|---|
| `2/3 + 1/4` | Construct | Valid candidates for both operands in compatibility evidence. |
| `1/2 + 1/3` | Inspect/keep/repair | False left numerator and valid right candidate. |
| `1/3 + 1/4` | Inspect/keep/repair | Valid left candidate and false right numerator. |

Resolve exact current IDs/revisions from the catalog. The addendum gives candidate
examples; validate them algorithmically. Cover both patterns on all three
instances as automated compatibility evidence (six pairs), not six mandatory
learner episodes or six hand-written implementations. Initial learner mapping
is fixed and versioned. Authored stimulus truth/error location must vary so
always-change or fixed-side shortcuts cannot solve the sequence. Expected
answers derive from deterministic exact math, not redundant manually maintained
model-answer records. Reject missing candidate sides, mismatched targets,
unsupported identities and other malformed pattern inputs.

## Requirement 3 — Honest state, assistance and replay

Distinguish learner-constructed, authored-then-confirmed, learner-repaired and
provided forms. Preserve source candidate, submitted action/form, classification,
recovery and assistance. Validation does not imply a learner decision. Requested
help stays local and preserves drafts; it must not fill or accept the answer,
trigger unrelated global escalation, or disappear from history when closed.
Adapt Plan 25 help only where meaningful; specifically explain inspect-help's
stimulus/answer boundary at Requirement 0. No-help means unassisted-in-app,
not independent or mastered work.

Pin problem/content identity, definition, pattern ID/revision, target, candidate
data revision, support and ordered intents for reconstruction. Replay reproduces
the same stimulus and work. Retry preserves the assigned pair but clears answers,
help and recovery; Next selects the next fixed vetted association only after
completion; return/re-entry starts the stable first association. Preserve selected
view/settings. No automatic advance, silent wrap or generated fallback.

## Requirement 4 — Evidence against the actual objective

Automated evidence covers all six pairs, full completion with exact classification,
valid keep, false keep, valid repair, invalid repair, valid unchanged submission,
withholding, assistance/replay, reset and malformed admission. Use deterministic
math to verify values; model review should focus on instructional and architectural
differences rather than rechecking elementary equivalences by hand.

Browser evidence must show both patterns on multiple problem identities, both
views, relevant support/applicability, correct/recovery/help and completion states.
Map deep versus swept cases explicitly; do not demand every Cartesian combination.
Include real keyboard correction/completion, browser touch with fields tapped
before tool-assisted text entry, reduced motion, and both 360×740/360×752 layouts.
Observe actual focus without repairing it in the harness. Verify questions and
controls reachable through ordinary scrolling, no horizontal overflow and concise
rendered copy. Add a wider desktop sample for both patterns. Capture screenshots
with captions indicating problem, pattern, state and input mode.

Separate authored inspection stimulus from withheld answers. Check mounted text,
hidden/accessible surfaces, summaries and relevant scene output for premature
corrected forms, validity cues, operation result and omitted-task remnants. Seed
an answer/validity leak and an omitted-task remnant independently; prove intended
failures then restore and pass cleanly. Preserve legacy route objects/assertions
and applicable reciprocal controls, adding meaningful new witnesses rather than
rewriting old cases to bless the new definitions. Reconstruct a preimplementation
legacy envelope as an independent compatibility oracle.
