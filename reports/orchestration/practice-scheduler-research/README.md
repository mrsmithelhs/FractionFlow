# Practice scheduler: external research workflow

Prepared 2026-11-04 for owner-run ChatGPT Deep Research and analogous Claude/Gemini
web research tools. This is not a repository-agent delegation or a request that
web tools access private/local files. Plan66 governs later synthesis, not execution
of the web services or adoption of their conclusions.

## Run and return

1. Copy the ENTIRE `deep-research-prompt.md` into each provider's research tool.
   It contains the project snapshot and constraints; no repository attachments are
   required. Run the three independently with the same questions. Do not provide
   another provider's output before completing an independent report.
2. Ask for the named downloadable Markdown file. Save each original in `incoming/`
   using its provider filename; see that folder's README. Do not edit its citations
   to make it look verified. Keep a dated new version for retries or continuations.
3. Tell FF Orch 12+ which files arrived. If a provider cannot complete, record that
   and let the owner decide reduced-coverage synthesis rather than invent a return.
4. Under Plan66's scope gate, inventory evidence and verify load-bearing claims
   before recommending a scheduler contract. No file arrival alone starts source
   work, changes learner data collection or validates an adaptive policy.

The shared brief covers four connected questions: evaluated prior schedulers;
sparse/assisted learner evidence; challenge/support/review composition; and learner
pacing/override. This is three independent provider reports, not twelve research
runs. No real learner records or credentials are supplied to web tools.

## Synthesis discipline

Retain a source-keyed ledger with provider/claim IDs, access level, actual study
population/intervention/comparator/outcome, confounds and applicability. Deduplicate
papers and reused cohorts/datasets. Distinguish learning outcomes from prediction
accuracy, engagement and product claims. Verify every claim used to justify a
decision against its original; mark other material as unverified lead where needed.
Preserve disagreement and “not found” results rather than manufacture consensus.

Proposed operating thresholds and policy ratios remain hypotheses. Strong evidence
for a learning ingredient is not evidence that our particular selector works.
Adult MOOC/certification evidence needs an explicit transfer argument for children
and fraction tasks. Start with a credible simple authored/rules baseline, uncertainty
and learner override. No identity, cloud requirement or runtime generative math.
