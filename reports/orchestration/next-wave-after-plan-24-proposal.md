## Acceptance discipline learned from Plan 24

- Read each rendered question, heading, feedback and help cue together. Require one
  visible question per learner decision, with native label/legend association. Help
  must contribute reasoning rather than repeat the prompt or answer it for the learner.
- Check the actual task before capturing; a filename or report label is not evidence
  that the screenshot represents that task. Review whole screens and exact visible copy.
- Exercise open/close, invalid submission, repeated identical invalid submission,
  opening after recovery, view switching, retry and return/reentry with mounted controls.
  Assert visible cue and label/ARIA agreement, retained work and connected focus.
- Use 360px layouts plus representative Chromebook CSS widths/zoom, keyboard, emulated
  touch, linear access and reduced motion. State actual device/AT/observation limits.
- Validate every admitted denominator/condition against complete authored paths, not
  just arithmetic validity. Failing-first/seed evidence must discriminate the defect.
- Review one source increment at a time. Owner rendered/agency acceptance and any
  deployed-candidate review remain distinct from passing tests and local commits.
