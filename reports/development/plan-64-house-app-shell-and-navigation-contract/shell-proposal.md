## Existing representative shell inventory

Common DOM order in `src/app/app.js` `createShell`: view switch, navigation (status, legacy Next when applicable, return, record notice), active visual/linear task, support controls (Help, Replay, restart). Navigation and view controls are right aligned flex rows; support wraps; these controls use the secondary treatment. Individual renderers place direct progression in the task's result/action area. Help can move into the task and is task-specific. The visual/linear switch reads “Read the steps” / “Show the picture”, updates `aria-pressed`, preserves applicable drafts and transfers task focus where supported; gestures are cancelled or composition flushed as appropriate. Restart “Try this problem again” installs the same item fresh, clearing episode UI work; it does not restart the session. A successful fresh install focuses the episode landmark (with a task-specific exception). Return focuses the entry heading. These are source observations; geometry and actual focus visibility await mounted checks.

## Proposed maintained contract and literal copy

Proposed `docs/design/app-shell-navigation-contract.md` should separate implemented rules from future migration, name app ownership of destination, state/lifetime/focus and descriptor, renderer ownership of task and local progression placement, and record-controller ownership of observation capture/storage. Reference Plan 52 feedback and `docs/design/episode-presentation-contract.md` rather than duplicate them. Explicitly document the existing standalone and accepted-intermediate-session no-dialog exceptions and the post-commit display-failure boundary; do not claim all episodes certified.

- One shared `STRINGS.app.returnButton`: **“Back to start”**, for global return and final session descriptor, both actually reaching entry. Keep final session global return hidden.
- View switch **“Read the steps” / “Show the picture”**; restart **“Try this problem again”**; normal progression **“Next problem”**, session transition **“Next: compare and find the distance”**, completion **“Practice complete.”**; preserve existing task-specific Continue and Help.
- Preserve modal **“Leave this practice? Your place will not be saved.”**, **“Stay”**, **“Leave”** and existing triggers. It describes session position, not the record; no new policy is proposed.
- For session refusal propose exact strings **“This problem could not be restarted. Try again or go back to start.”** and **“The next problem could not be opened. Try again or go back to start.”** Keep standalone **“This problem is not ready. Try again or go back to start.”** and the existing unrecoverable display notice. Verify the correct message survives render; do not change failure boundaries.
- Arrangement: keep view switch then navigation ahead of task in DOM and keyboard order; return remains secondary and at the top; task-owned progression remains with accepted work; restart remains secondary after task. Use existing wrapping and focus treatments, with only necessary scoped alignment/spacing changes demonstrated by rendered evidence. This avoids moving Help or adding a redundant completion action.
