## Journey and lifecycle

Select A, place at step 6; Check names B/C as unplaced without grading A. Select B, place step 4; select C, place step 6: A/C share one anchor, then move C to step 4 to share with B. Check accepts record 1. Before acceptance a wrong complete map yields per-member feedback; selecting any member and repositioning it clears its feedback and requires a new full Check. Any two or all three may occupy an arbitrary same draft anchor, including wrong ones; no individual placement is automatically accepted. Check focuses a connected feedback summary and member feedback remains associated. After acceptance use the shared progression descriptor/transaction for Next or final Back; destination preparation failure leaves current accepted state and history inspectable and offers a refusal message.

Pointerdown selects that member; 6 CSS px movement starts drag, with no committed change until valid release. Escape, pointercancel, lost capture, and outside release discard local hover and retain prior placement, including null. Tap axis chooses nearest candidate; direct previous/next controls and linear step choices dispatch the same candidate IDs. From unplaced, left explicitly selects 0 and right explicitly selects N, announced before any further move. Selection/list and status are stable in authored order; duplicated visual tokens are pointer-selectable, `tabindex=-1`, and list provides sequential keyboard selection. Linear path presents same three statuses and candidate choices, Check and feedback; neutral live messages include co-location counts, never a correctness conclusion. More/Less share candidates and truth; More shows partition marks, Less reduces decorative marks. Support freezes per episode; optional help is non-answer-bearing and provenance records use, not independent mastery.

Same episode view/help/resize/remount preserves selected member, committed map, assistance and feedback. App owns focus restoration to connected selected-member/list or equivalent control, fallback task heading. Render handles validate generation/context/phase, are revoked on destroy, replacement, reset or navigation; do not retain stale nodes. Restart installs fresh empty episode; Next and re-entry likewise. Geometry recalculates from current visible frame. Avoid source-bar/task leakage and unnecessary prompts.

## Proposed paper geometry (CSS pixels; subject to browser proof)

At 360px viewport, allow 16px outer margins; task container <=328px, axis inset 26px each side (axis >=276px at that width). Tray is a separate flow block above a reserved label/axis area, with fixed minimum occupied height during drag; it holds only unplaced tokens. Reserve three nonoverlapping rows of at least 44px height plus 4px row gaps above axis. All three placed token boxes are at least 44x44, constrained within container; content may grow with text, increasing row height rather than clipping. Each member permanently uses its authored row A lower, B middle, C upper, regardless of candidate: this bounded packing solves both same and neighboring anchor overlap vertically, with no hidden or overlapping interactive targets. Clamp each box horizontally to the container; draw a noninteractive tether from the box to its unchanged exact anchor. Use a single point per candidate and common anchor x = x0 + i/N*(x1-x0). The distinct rows add vertical space, not mathematical positions. At enlarged text remeasure row heights and permit vertical scrolling. If measured available width cannot contain one 44px control, fail visibly rather than overlap or falsify coordinates.
