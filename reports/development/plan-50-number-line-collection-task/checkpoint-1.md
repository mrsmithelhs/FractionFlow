## Implemented boundary and wires

`getEpisodeDefinition('phase-4-number-line-collection','1')`, `createEpisode`, `applyIntent` and `episodeStateSnapshot` are the one public episode boundary. The task-specific module is a reducer behind that boundary, not a second public event history. Set `number-line-collection@1`, items `collection-01` through `collection-04` each revision `1`, member IDs `a,b,c` and `step-0..step-N` are fixed; context contains those identity keys plus purpose, lattice and exact original ordered member forms. Context validation reconstructs registered data and rejects changed identity/forms/order, allowing property-key reordering. Admission accepts three distinct IDs, canonical nonnegative original forms in [0,1] with denominators 1..8, lattices 4/6/8, exact matching, at least two distinct positions and an unused offered candidate; unsupported content throws before learner evaluation. Derived positions are not stored in records.

Public state uses common `fractionflow.episode-state/v1` and `revision` as chronological accepted-event count; `placementRevision` changes only on an actual placement change. `evaluation.placementRevision` names the checked map; `unchecked` after edit prevents prior feedback from being current. Changing member clears that member's feedback; other retained feedback is explicitly historical whenever status is unchecked. Selection does not change the map, placement revision or verdict. Re-selecting the same member and placing it again at its same location are no-ops: same state, no event. Invalid, stale, out-of-phase and foreign-context intents throw without changing state/history. Help requests are recorded individually, including repeated requests. Committed placements, selection, support and history reside in state; transient hover and cancellation do not create intents.

Literal intent shapes are `select-collection-member {context,memberId}`, `place-collection-member {context,memberId,candidateId}`, `check-collection {context,revision}`, `request-collection-help {context,helpKind:'placement'}` plus `type`. Context has exactly setId/setRevision/itemId/itemRevision/definitionId/definitionRevision. The check revision is the placement revision. Incomplete checks mark unplaced versus not-graded; complete wrong checks mark each correct/check-placement and preserve all work; correct Check establishes the complete map atomically and resolves. All members are editable until acceptance; draft collisions have no correctness meaning. `intentHistory` is the ordered accepted action stream; assistance events contain their chronological event revision and accepted provenance includes the assistance history. Support is frozen to existing More/high or Less/medium profiles. `plan50-static-collection@1` explicitly marks display, choreography and connection-making not applicable, with focused key-beat prompt cadence; other conditions are refused, including later `withActiveCondition` changes.
