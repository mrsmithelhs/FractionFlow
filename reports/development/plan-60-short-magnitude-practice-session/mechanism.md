## Launch and state contract

Proposed seams: compact `src/app/magnitude-session.js` for authored manifest, admission, pure session navigation and preparation adapter; minimal integration in `src/app/app.js`, copy in `src/render/strings.js`, and only necessary `src/app/styles.css` layout. Names may be refined without widening scope. Reuse `getPracticeType`, `getEpisodeDefinition`, task context resolvers/validators and `createEpisode`; share/extract the current registered-item preparation seam as needed rather than fabricate a mixed practice type. Do not change existing standalone sets. Current `registeredItemEpisode` and `createInitialState` show construction is task-dependent; `prepareProgressionTransaction` assumes one type, so cannot itself advance this manifest across types.

Pure session state holds manifest identity, index, active lifecycle and a session generation token, plus frozen admitted support selection; episode state remains the existing public task state. The mounted app owns current episode, local draft/help UI, access view and existing episode generation. Preparation takes the next literal reference and current captured generation, resolves and constructs a candidate without mutation. Commit only if session and episode generation, current index, resolved status, expected next index and transition lock still match; install candidate and advance index as one synchronous transaction. Any refusal/throw/missing or invalid candidate leaves old state, draft/help and index unchanged. Invalidate old episode/session controls on successful install, restart, exit and navigation; reject duplicate or stale actions. A failed candidate must never become visible. Final index is normal exhaustion, not error. Restart prepares and installs the same entry fresh and invalidates old callbacks; a new session always starts at index 0. Wrong/incomplete responses and correction remain task-local.

The resolved predicate must require full task completion: comparison `status === resolved` with established comparison; distance `status === resolved` with established comparison AND distance, never merely its accepted intermediate comparison. Existing `createEpisode` and task reducers preserve compare→resolve and compare→distance→resolve, source forms, scene withholding, provenance, support/help and replay. No new replay epoch is planned. Pure tests will construct real contexts/episodes and exercise admission, order/reconstruction, both supported configurations, invalid revisions/duplicates/definitions/configuration, all transition failures and retries, unchanged old state, no auto/double advance or skip, stale generation, restart, fresh start and final exhaustion; include real task completion and replay checks. ## Mounted lifecycle, copy and access

Entry alongside standalone goals: “Compare fractions, then find a distance.” Cue: “Your place in this practice is not saved.” Start prepares before installation; initial failure stays at entry with neutral retry and practice routes. Keep the selected visual/linear mode and reduced-motion behavior across episodes. Each new episode gets fresh drafts/help; the accepted old result remains until deliberate Next. At item 3 show “Next: compare and find the distance” and launch item 4 directly, whose own comparison precedes its distance. Final accepted result stays visible with “Practice complete” and “Back to practice”; no score, empty Finish or extra Next.

One session-aware Back to practice action replaces the existing global exit in session mode. Active unfinished work opens a modal dialog: “Leave this practice? Your place will not be saved.” with Stay and Leave. Capture the invoking focus and do not rerender/reset underlying task on open or Stay; keyboard focus enters the dialog, remains within it, Escape acts as Stay, and Stay returns focus to the invoking control while retaining exact episode, draft and help. Leave invalidates session/episode generations, clears session and drafts, returns to practice and focuses the entry heading or session entry. Resolved results return directly. Browser reload, tab close and external navigation discard ephemeral session without a beforeunload promise; no session progress written to browser or remote storage. Ensure hash navigation cannot accidentally install standalone practice while a session is active; in-app hash navigation must use the same exit decision, while actual reload/external navigation remains unprotected. Do not leave a session-resuming fragment; reload returns to the practice entry.

On Next preparation failure preserve the accepted result and index, show “The next problem could not be opened. Try again or return to practice.” and offer retry and return. Focus the actionable notice once; no math error or lost old state. On successful transition focus the existing meaningful episode landmark, with one announcement and no duplicate task heading. Dialog, controls and feedback must remain keyboard reachable and visible at 360×740 and Chromebook 1093×614 DPR 1.25, 200% text and reduced motion; stack/wrap without clipping. These are planned checks, not accessibility or device claims.

Journey A: start; incorrect/incomplete response and correction on item 1; deliberate Next to reversed pair, optional comparison help, restart current item, then equality; cue leads to new pair and its comparison, then distance; inspect final result and return; fresh entry starts item 1. Journey B: open help and enter unfinished work; choose exit and Stay, retaining exact work and focus; Leave discards it. Separately force next preparation failure, inspect old accepted result, retry successfully or return; reload mid-session returns to fresh entry. Verify standalone, keyboard/linear and pointer/touch-context runs, actual reload and session-related durable-write monitoring; no inference of learner outcome, real assistive technology speech or physical-device usability.
