## Registered content and admission

Propose a compact Plan 84 data module with four stable item IDs and item revisions, each containing the original mixed form as three integer strings and four ordered numerator/denominator string pairs; a separate versioned membership list fixes item order. The records exactly match the Plan 84 table, including `1 2/8` and `10/8`; no answer slot is stored as grading truth. Admission checks exact registered record and membership including revisions and order, exact object keys, unique IDs, canonical integer strings, whole 1, denominators 2, 4, or 8, proper nonzero remainder, common source denominator for options, values within 0–2, four distinct exact option values, and exactly one option equal to `mixedToImproper(createMixedNumber(...))` using the math core. Batch validation rejects duplicate, missing, unknown, altered, ambiguous or revision-mismatched records. Preserve authored strings separately from normalized math values so notation is never reduced in presentation. Test that the computed correct indices are 3, 1, 2, 4, respectively, but never grade by that table.

## Episode and projection

Add a dedicated revision-1 definition, static condition and bounded episode, following the Plan 58 context and Plan 82 membership patterns. Initial state has no selected option, an unchecked evaluation and a draft revision. A select intent accepts only a registered choice identity, increments the draft revision on change and clears feedback. Check carries that revision and exact set/item/definition context; reject stale, forged or malformed intents. Empty Check yields a selection cue; wrong Check preserves the selection, marks retry and allows editing; changing it clears feedback. A correct Check compares exact admitted values, records response provenance and resolves immediately. New attempt and next item instantiate a clean draft; display order never shuffles. No placement, reflection or Finish beat is introduced.

The active projection exposes the supplied mixed form, ordered options, selected choice and evaluation only; it must not expose the target, computed correct identity, line geometry, marker or completed equivalence, even on an incorrect Check. Options themselves necessarily remain visible. On resolution only, project both authored forms, the derived count explanation and one exact shared point, with 0, 1 and 2 benchmarks and denominator subdivisions. The render layer consumes that validated projection rather than deriving correctness. Inspect scene payload as well as DOM and accessible names, including after wrong Check and during replay.

## Presentation, focus and view switching

Use stacked symbolic notation and one native radio group with a clear legend, initially unselected, and a single Check in both visual and linear modes. Radio keyboard operation and ordinary taps provide non-drag access. Follow house feedback styling and focus conventions: focus the feedback once following Check, retain a stable focus key on ordinary rerender, and focus the existing progression action after acceptance as appropriate to the house contract; avoid duplicate live announcements. View switching remounts the view from the same episode state, preserving selection and feedback and moving focus to an equivalent meaningful control or feedback without submitting; test actual focus behavior. Accepted linear text identifies 0, 1 and 2, equally sized whole intervals, the shared point, both authored forms and the count explanation.

Reuse Plan 53's two-whole geometry principle: `2*d` equal subdivisions, benchmark indices 0, d and 2d, and the accepted numerator at index `d + n`; the normalized horizontal coordinate is that index divided by `2*d`. Use one marker and anchor both labels to that marker, not two independently positioned points. Plan 53's renderer mixes geometry with placement gestures, so use its geometry as precedent rather than importing its interactive renderer wholesale. For eighths at 200% root text, allow labels to wrap or occupy separate rows connected to the shared marker; reserve vertical space and clamp or otherwise contain the label group within the frame without moving the marker. Verify visually rather than assuming CSS achieves this.

## Routing, replay and boundaries

Register a standalone practice type and membership-driven items in the existing chooser/entry category, with its own set, item and definition revisions. Integrate context resolution, condition, episode dispatch, scene projection and renderer through the existing app paths. Reuse existing progression for next/fresh attempt and preserve view state during switches. Add a distinct new replay envelope/content-identity version and kind, reconstructing the exact registered set/item/revisions and condition and replaying only validated Plan 84 select/check intents in deterministic order; reject altered identities or intent shapes. Do not repurpose prior replay versions; run historical replay regression coverage. The current replay module lists versions through v19, so reserve a new version after checking the live registry at implementation time.
