## Theme, slots and actual tasks

Theme: compare fraction magnitude and use the same-size-parts idea to locate a gap on a number line, with one half as a shared landmark. Three is an authored, finite design choice, not an efficacy claim. Each slot below admits exactly the listed registry references; no new content is proposed.

| Slot | Eligible record(s) | Purpose and connection |
| --- | --- | --- |
| 1 | `plan45-compare-02` (5/8, 3/8) or `plan45-compare-09` (3/5, 3/7) | Compare either equal-size eighths or equal counts of differently sized parts. Both pairs straddle 1/2. |
| 2 | `plan45-compare-10` (3/8, 5/9) | Both amounts straddle 1/2, as does either slot 1 pair; 02 also shares 3/8, while 09 offers another same-count contrast. Comparison remains the same relation-selection interaction. Its half-benchmark reasoning tip is available on request, not automatically displayed or guaranteed to be used. |
| 3 | `distance-01` (2/8, 6/8) or `distance-04` (5/6, 2/6) | Each pair lies on opposite sides of 1/2 (4/8 or 3/6). Compare first, then express the gap as 4/8 or 3/6 respectively; 01 also returns to eighths when slot 1 is 02. This is a new task, not a repeat of either preceding pair. |

In slots 1–2 the learner chooses a relation and checks it, with existing optional notation/reasoning help, one chosen model and common-denominator construction; More adds the general prompt. At the bridge, the distance episode retains relation choice/check and optional comparison tips/model, then asks for the separation with a number-line representation and optional distance tip or both amounts. More supplies the distance cue; Less leaves the tip request available. Support stays fixed for each episode. This is an instructional rationale from the authored records and task/renderer code, not an observed learner outcome or assertion that the benchmark is explicitly shown by every aid.

## Selection, reproducibility and fallback

Propose a document-local, monotonically increasing nonnegative safe-integer start counter, initially zero; reserve and increment it once per Start activation, independent of all learner information. Its value is the explicit selection input: slot 1 picks 02 for even inputs and 09 for odd inputs; slot 2 picks 10; slot 3 picks 01 when floor(input / 2) is even and 04 otherwise. The same input and unchanged policy/registry reproduce the same output. Each new start receives a fresh input within the document; reload resets it, and equal outputs across starts remain permissible in the general contract. Counter exhaustion or unavailable candidate preparation fails closed to the fallback rather than wrapping. No clock, record, profile, past answers, support, access path or remembering state is an input. Support is independently checked for constructibility, not used to select membership.

Two realizable policy outputs are input 0: `[plan45-compare-02, plan45-compare-10, distance-01]`; input 3: `[plan45-compare-09, plan45-compare-10, distance-04]`. Inputs 1 and 2 independently combine the alternate first and bridge slots. Both include comparison and distance episode types. The policy chooses a reference for each slot at launch, not between two stored whole-session manifests. It does not claim large variety: the first and bridge slots each vary between distinct underlying pairs; the shared half benchmark and relation interaction retain continuity. The same underlying unordered pair is deliberately not repeated within a visit; compare fractions by exact normalized values when enforcing pair uniqueness, so reversed or equivalently written forms cannot evade it. Also reject duplicate item identity. The comparison and distance pairs in both examples are distinct.

On Start, construct the full proposed ordered reference list and validate it before installation: exact scheduler identity/revision and shape, exact slot count/order and each slot's full allowed reference including revision, at least two episode types, no repeated item or normalized unordered underlying pair, and all registered association/context/definition/recipe/support checks. Resolve and construct every episode through existing authoritative preparation before a controller is installed. If selection or any candidate, slot, support or preparation fails, try the exact existing `COMPARISON_SESSION_MANIFEST` (Plan 69) through its existing admission and prepare all four; never install a partially prepared scheduled session. If that also fails, leave entry and chooser usable and show a concise unavailable notice. No reroll or unbounded search is required. This fallback is intentionally comparison-only and is not claimed to meet the normal mixed-output requirement.

The admitted result is cloned/frozen and retained by the session controller for the entire visit. Retry, help, selected model, starting support, visual/linear path, remembering and answers cannot change membership or order. Next/restart continue the existing prepare/independent reconstruction/commit ticket lifecycle; exit or reload retires the ephemeral visit. Start opens the first problem directly, with no picker. Final accepted result offers Back to start; preserve current refusal, display-failure, focus and exit behavior.
