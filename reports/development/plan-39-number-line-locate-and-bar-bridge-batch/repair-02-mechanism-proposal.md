## Upstream exact scale and linear descriptions

Add an exact scale projection in the Plan 39 task/content or instructional projection layer (not `src/render/`): collect denominators of every selectable offered fraction for the active support mode and the partition unit fractions for partitioned support, include denominator 2 for the half benchmark, then calculate their LCM using the existing exact math utilities. Reject a scale beyond a named small bound (recommend 12 pending parent review); require every offered fraction to map to one unique integer location `numerator × (scale / denominator)`. Generate frozen `{id, form, unitsFromZero, totalUnits, ...}` descriptors from that result. For current records, calculate the bound across all 16 item/support contexts before coding; current forms appear to need at most 8 subdivisions, but this is an inspection estimate until a script/test evaluates the exact registry.

The renderer consumes these descriptors and never computes rational scale or correctness. Linear copy is `Choose a location.` followed by letter-first labels such as `A: 3 steps from 0` under `0 to 1 has 8 equal steps.` The common scale and each unit distance identify an actual location; A/B/C/D are only option handles and do not carry truth status. Generate the same precise location descriptions for visual accessible names. Once a selected location is accepted, generate resolve copy from the accepted candidate descriptor and validated source fraction, for example: `You chose 6 of 8 equal steps from 0. That is 3/4 of the way from 0 to 1, matching 3/4.` Do not show the source bar, aligned shaded portion, connector, or bar-derived help text in locate, including hidden nodes and accessibility attributes. At resolve, show the bar reconstructed from the source fraction plus the connector to the accepted point. The linear resolve view uses the same accepted unit distance and source fraction relationship, not a generic line description.

## Pointer, keyboard, reset and cancellation contract

Start with the symbolic source fraction in the prompt and a separate movable fraction token in an unplaced tray outside the line. Its accessible name states the source fraction and that it has not been placed. Keep an explicit Check control disabled until a location is pending. Dragging the token onto the track, or tapping/clicking a track location after activating the token, snaps to the geometrically nearest offered marker; tapping directly on the track can also choose the nearest marker. The snap routine compares pointer x against the already projected marker centers only; it has no target/correctness input. Equal geometric distances break toward the lower visual position, then stable candidate order, and this policy is covered by a boundary witness.

Use Pointer Events and pointer capture for an active token drag. On pointerup, commit only the nearest offered candidate to the pending local selection. On `pointercancel`, lost capture, Escape, or vertical-scroll takeover, restore the token to the unplaced tray and leave Check disabled. Apply `touch-action: pan-y` to the horizontal placement surface/token drag affordance so vertical page scrolling remains available; cancel a gesture when vertical movement clearly exceeds horizontal movement. A tap-to-place alternative and native linear radio choices remain available. Keyboard users use the native radio group or focusable candidate controls and Check; never require drag. All non-drag controls and hit targets stay at least 44×44 CSS px.

Pending placement is view-local/transient and does not enter episode state. On visual/linear view switch, remount, or task reset, return to unplaced and clear the pending candidate; focus the prompt/location group after switch or reset. On browser back/forward replay, only previously checked proposals reconstruct state. Help toggling does not serialize; its locate guidance describes using the equal-step scale and does not reveal a bar/target clue. These reset choices bound stale pointer state and are explicitly witnessed.
