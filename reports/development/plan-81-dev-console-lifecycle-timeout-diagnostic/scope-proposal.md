## Hypotheses and discriminators

| Candidate | Observation that would support it | Falsifier / matched control |
| --- | --- | --- |
| Bind, child startup or readiness delay | Long spawn-to-ready IPC or ready-to-valid HTTP interval, or collision start-error/exit interval, at the deadline | Normal intervals in a timeout with time consumed later; compare collision, learner and prototype under the same run and identical uninstrumented controls. |
| Cooperative shutdown or exit delay | Long stop request-to-stopped acknowledgement or acknowledgement-to-child exit | Both intervals short while another named phase consumes the budget; compare each helper and successful runs. |
| HTTP or independent-server cleanup delay | Long independent listen/fetch/body/close, post-stop fetch, or final port-closure check | These intervals short in the timeout; distinguish an HTTP response/body wait from `external.close()` and from helper stop. |
| Checkout, scheduling or concurrent load | Matched uninstrumented timings shift with checkout or whole-suite context, with comparable dependency provenance | Similar distributions under matched conditions, or a specific slow phase independent of the varied factor. Correlation alone cannot identify the load source. |
| Probe effect or port collision race | Instrumented runs systematically slower than paired unchanged runs, or an ephemeral port is claimed between release and bind | Similar paired timing and observed ownership/bind results. A port chosen by listen(0) then released is not reserved; record unexpected collisions rather than attributing them to lifecycle code. |

## Probe map and interpretation

Use `performance.now()` in the relevant process, with a run ID, sequence number and relative monotonic elapsed time. Parent and child clocks are not assumed comparable: report durations within each process and correlate IPC send/receive by event and run ID, rather than subtracting unrelated clock origins. Capture start and completion/error around each allocation/close, independent Vite creation/listen, menu prompt/input/dispatch and return, collision attempt, independent HTTP fetch and body, learner and prototype menu cycles, post-stop fetches, independent close and final fetch. At the manager/helper boundary record spawn attempt/result/error and owned PID, IPC ready/start-error, HTTP validation start/end, stop send, stopped/stop-error, exit and stopAll return; helper-local startup, listen and close events distinguish internal work. Preserve the actual await and event order. Record the last observed completed event and first expected missing event on timeout, with the timeout/censoring boundary and measured phase durations on passes. A missing log is not itself proof that the event did not occur.
