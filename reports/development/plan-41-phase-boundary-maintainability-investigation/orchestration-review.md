## Refinements for the next packet

1. **Keep the agreed sequence; reduce packet overhead.** Recommend guards first,
   then baseline measurement, operate slice and its evaluation, then Plan 39.
   These can be stages of one separately approved refactor packet with explicit
   review stops and scoped commits. Plan 41's prohibition on shared test edits
   does not require two new packets. Repair only guards needed for the slice;
   avoid a general test-harness cleanup prerequisite.
2. **Use the same repaired guard baseline for both evaluation arms.** Arm A is
   after guard fixes but before extraction; arm B adds extraction. Use separate
   isolated workspaces and cold agents with the same brief. Never apply both
   experiments to the production tree or require abandoning a useful extraction
   because one run opens an extra file. A parity regression blocks acceptance;
   files/concepts/wrong guesses are noisy supporting observations. The report's
   rigid single-run rule and 'indistinguishable therefore Vue next' conclusion
   overstate what this small comparison can establish. Permit an inconclusive
   finding and owner judgment; no automatic funded comparison follows.
3. **Make the follow-up edit discriminating and temporary.** Copy-only changes
   already flow through `strings.js`; they need not exercise duplicated wiring.
   Recommend the proposed error association plus a modest agreed copy change in
   isolated evaluation arms, not an unexplained permanent learner-copy revision.
   Missing/cleared errors must not leave dangling or stale `aria-describedby`;
   retain any other descriptions. Separate experimental permission from adopting
   that change into the product. Exact experimental wording belongs in the source
   packet before either arm starts.
4. **Correct scope of the region sketch.** Recovery DOM is currently built before
   `case 'operate'` in each renderer. The proposed module cannot claim to own that
   paragraph while also excluding recovery extraction and requiring its element
   remain inside the controls container. Prefer leaving recovery rendering with
   the shell for this first slice, passing explicit error identity/association
   information if needed. Alternatively propose a very small explicit relocation
   at the mechanism gate, with parity evidence. Do not silently broaden scope.
   Specify handle invalidation/reacquisition, raw empty/partial drafts, fraction
   versus single-input behavior, and focus targets for connected visible controls.
5. **Do not promise locate reuse in advance.** The operate handle is a candidate
   pattern for preview state, not proof Plan 39 needs the identical API. A preview
   candidate is semantically different from numerator/denominator strings. Let
   Plan 39 validate or adapt the minimal interface without inheriting arithmetic-
   specific assumptions. No representation framework or fixed generic draft union.
6. **Retain no-refactor as a legitimate counterfactual.** Duplication establishes
   cost/hazard, not net benefit after extraction/testing costs. H5 is not logically
   falsified merely because guards cannot remove duplication. The evidence favors
   a bounded trial; it does not prove every alternative inferior. Also, zero
   matches is correct behavior for `notHasSelector`; the issue is relying solely
   on a negative selector without positive context, not the operator itself.
